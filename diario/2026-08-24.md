**Context:** a day with no new code — most of the time went into tracker housekeeping, closing out
issues whose fixes had already shipped weeks earlier but never auto-closed because the merge target
wasn't the repository's default branch. Also started (not yet merged) a design write-up for an
email-verification feature on the registration flow.

## What I did

### 1. Backlog cleanup
Closed 22 issues in two batches, verifying in each case that the underlying fix was a real ancestor of
the integration branch before closing it — not just trusting the pull request's "merged" status.

### 2. Registration email verification — design write-up
Drafted the requirements and design for sending a verification email as part of registration, via a
background job queue and a transactional email service. Left in a draft branch, not merged yet.

## Ops
22 issues closed, no pull requests, no features shipped — a maintenance day.

## Learnings / technical decisions
Verifying real ancestry against the integration branch before closing an issue "because its pull
request merged" avoids closing something that actually landed on a branch that never made it to the
shared branch.

## What I could do better
The volume of issues needing manual closure is a symptom of a process gap (pull requests targeting an
integration branch instead of the repository's default branch) that keeps getting absorbed as periodic
manual cleanup instead of being fixed once at the source.
