No commits today. The entire working day went into a failed attempt to get the client's mobile app
running locally to test on a real device, on a Windows + WSL2 setup.

## What I did

### 1. Attempted to run the mobile app locally — RAM overflow
- Bringing up the monorepo's bundler and build tooling inside WSL2 alone was enough to saturate
  available RAM — the machine became unusable (constant swapping, hung processes) before reaching any
  testable state.

### 2. Attempted physical-device testing — blocked by USB passthrough
- WSL2 doesn't expose the host's USB bus directly to the Linux kernel, so the device-bridge tool
  couldn't see the phone connected by cable. Would have needed an additional USB/IP bridge that
  wasn't installed or configured.

### 3. Attempted a native Android emulator — blocked by nested virtualization
- The emulator needs its own hardware accelerator to start at a usable speed. With the host
  hypervisor already in use by WSL2, the emulator competed for the same virtualization resource —
  it either failed to start or ran too slowly to be usable.

## Ops
- 0 commits. No product progress — the full day lost to local-environment infrastructure, without
  reaching a point where I could run any test (unit, e2e, or manual) against the app.

## Learnings / technical decisions
- WSL2 is not a reliable environment for mobile development when you need both an Android emulator
  and physical-device testing at the same time: the nested virtualization layers compete for the same
  resource and end up blocking both testing paths, not just one.

## What I could do better
- I should have validated the mobile dev environment (available RAM, WSL2 compatibility with Android
  tooling) before actively needing it for a feature — I lost the entire day to an infrastructure
  problem that was detectable ahead of time.
