## What I did

### 1. Closed out mobile checkout return
- Checkout confirmation no longer blocks navigation on a ~20-second backend polling window — it
  resolves as soon as the browser hands back control, with the real confirmation continuing in the
  background behind a small non-blocking indicator.
- A background list-reload call was still blocking navigation for a couple of seconds — reordered to
  navigate first, reload after.
- Merged the full feature.

### 2. Real auth bug: invite-by-email failed for new accounts
- Corrected a wrong assumption in the underlying spec: an internal registration endpoint does require
  the caller's own auth token (the backend needs it to send the account owner a confirmation email) — a
  wrong assumption had caused every invite to a brand-new email address to fail with a 401.
- Fixed the call to actually send that token — the only code path affected. Along the way, fixed a
  swallowed-error pattern that had made this exact bug much harder to diagnose from device logs in the
  first place: the failure handler wasn't logging anything on error, just showing a generic message.

### 3. Real contract bug: purchase-quantity + wrong field names
- Two compounding bugs in a purchase-quantity input: a clamping rule fired on every keystroke instead
  of on blur, so typing "3" produced "13"; and a purchase-type request always sent one purchase type's
  field names even for the other purchase type, which the backend rejected outright.

### 4. Real contract bug: wrong endpoint for a client-assignment action
- A client-assignment action was reusing a different action's shared endpoint, whose capacity check
  only covers one of the two resource types it's meant to gate — so assigning a client could fail
  whenever the *other* resource type was exhausted, not the one actually being consumed. An older,
  proven codebase never shared that endpoint for this action; migrated to the dedicated endpoint it
  always used, verified with a direct request and a live device test. Also fixed a raw backend value
  showing instead of a formatted label on the projects list, reusing an existing localization pattern
  from elsewhere in the same codebase.

### 5. Started a pagination feature — designed first
- Designed with an architecture-review pass before writing any code — a full blueprint covering both
  the immediate web change and the mobile follow-up.
- Backend: one endpoint that returned every active record unconditionally — confirmed via logs that a
  test account with 17 records loaded them all on a single page load. Added limit/cursor pagination.
- Same cursor-pagination pattern applied to a second, unrelated endpoint (a content-calendar feed),
  where the sort order is a multi-column compound key that a simple cursor predicate can't reproduce in
  SQL, so pagination happens in-memory over an already-sorted result.
- Consumed the new calendar endpoint on the web side; along the way fixed a live bug where a
  service was built from the wrong environment variable, silently falling back to a remote environment
  instead of the shared configured one — the same class of bug fixed elsewhere in this codebase earlier
  in the week.

## Learnings / technical decisions
- Three unrelated bugs today share the same root cause: code that assumed an API contract (auth
  requirements, field names, a shared endpoint) without verifying it against the real backend or an
  older, proven implementation. The pattern keeps repeating — verify the real contract before writing
  the spec, don't infer it from how it "should" work.
- Designing the pagination feature with an architecture-review pass before implementing left a
  blueprint that already covers tomorrow's mobile follow-up, not just today's web change.

## What I could do better
- The auth bug would have been much faster to diagnose if the original error handler hadn't swallowed
  the failure silently — that pattern should be on my checklist when writing any new error handler, not
  something I only fix after tripping over it.
