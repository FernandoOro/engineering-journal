### 2. Root-caused a navigation flash bug (late morning)
- Fixed a visual bug where a screen exiting via animation stayed mounted while the navigation state
  already reflected the destination route, briefly rendering a "not found" screen for one frame. A
  prior fix (from last week) was insufficient because it didn't cover this exact case — this one
  freezes the relevant value at mount instead of recomputing it live.
- Found that the fix's own regression test lived inside the app's route-root directory, where the
  bundler treats any file as a potential screen definition when building a release — breaking the
  release build with a module-resolution error. Moved the test out of that directory into a
  dedicated hooks location.
- Verified this time with an actual release build, not just static/unit checks — those alone don't
  exercise the bundler's route-tree packaging, which is exactly how the bug slipped through the first
  time.

## Learnings / technical decisions
- Last week's fix for the navigation flash was "insufficient" not from carelessness but because
  static/unit checks don't exercise the bundler's route-tree packaging — the only real verification
  for this class of bug is an actual release build, and I have that capability back in my local
  environment now.
- No test file should live inside the framework's route-root directory; the bundler treats it as a
  screen definition when packaging, not as a test.
