## Learnings / technical decisions
- A framework's dependency-injection mechanism doesn't need another dependency already attached to work
  standalone — my initial assumption on the research-area guard conflated "this route skips user
  validation" with "this route can't carry this kind of guard." Those are different things.
- Removing a rollout feature flag once test coverage is sufficient avoids accumulating "switches"
  nobody ends up using — the real rollback is version control, per pull request, per area.
- Mirroring the same backend fallback/alias logic in the frontend SDK the same day it was fixed on the
  backend avoids a case that's already solved on one side reappearing on the other.

## What I could do better
- The research-area guard was implemented twice in the same morning from a too-quick reading of a
  design note — reading the full reasoning (not just the one line that seemed to justify a shortcut)
  before writing the first attempt would have avoided the revert commit.
- The week closes with 2 pull requests still open and 1 pending test issue — real carryover, though
  each is documented on purpose, not lost.
