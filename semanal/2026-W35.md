# Week 2026-W35 (Mon Aug 24 – Fri Aug 28)

Almost the whole week's coding work landed on the frontend/mobile side: a Monday of pure backlog
cleanup with no new code, a Tuesday-Wednesday of closing out point fixes (an orphaned commit, a
shared-SDK promotion, older billing work picked back up), and a Thursday-Friday that executed a "real
calendar data" feature end to end — domain model through to UI and tests, on web then mobile.
Spec-writing tracked every piece in parallel, with a backlog of design docs merged in one batch on
Thursday. No backend commits landed this week.

## Frontend / mobile (fintech SaaS platform — client)

- **Done (Monday — tracker housekeeping):** closed 22 issues whose fixes had already shipped weeks
  earlier but never auto-closed, verifying real branch ancestry before closing each one — no new code.
- **Done (Tuesday — point fixes):** fixed a chat-drawer bug caused by a merge race between three
  back-to-back pull requests that orphaned an earlier "merged" fix; added an end-to-end regression suite
  for a payment-status banner/intercept feature; promoted shared plan-status display logic into a
  common SDK package used by both web and mobile.
- **Done (Wednesday — closing out + planning):** merged Tuesday's two pull requests; lined up the
  issues for a calendar feature to build the next day; picked back up an older billing/invoice feature
  written weeks earlier, rebased in an isolated workspace, and opened its pull request right as a
  scheduled meeting started in the early afternoon.
- **Done (Thursday — calendar feature, web):** two real billing/invoice-download fixes, then merged
  Wednesday's billing work; a calendar feature built end to end across six same-day pull requests —
  domain model, a service layer pulling real data instead of demo data, a documentation fix, a caching
  data-fetching hook, the UI itself with real states, and a dedicated test suite plus manual
  verification against a live local backend.
- **Done (Friday — calendar feature, mobile):** the calendar feature's mobile data layer wired to real
  data; a real bug fixed in an overview screen where a demo-mode flag and an item count had drifted out
  of sync; cross-cutting tests added for the new wiring.
- **Technical decisions:**
  - Reapply an orphaned fix as a fresh pull request rather than trying to recover the original commit —
    simpler and easier to verify than reconstructing the merge race that caused it.
  - Rebase old, unlanded work in an isolated workspace before integrating it, to avoid mixing a large
    amount of unrelated drift into a focused change.
  - Break the calendar feature into small, sequential pull requests (domain → service → hook → UI →
    tests), each closing its own issue — let all six merge the same day without anything blocking
    mid-afternoon.
- **Mistakes (root cause):** the orphaned chat-drawer fix — two back-to-back pull requests plus a third
  merge into the integration branch that absorbed the second pull request's base branch moments before
  it merged — left the fix off the integration branch with nothing in the pull request's own status
  showing it. Nobody caught it until the following day because there's no routine check that verifies
  real branch ancestry after a merge. Second recurring pattern: most pull requests this week target an
  integration branch rather than the repository's default branch, so automatic issue-closing never
  fires — hence Monday's 22 manually-closed issues, a cleanup that keeps recurring instead of being
  fixed at the source.
- **What I learned:** a pull request marked "merged" doesn't guarantee its commit lives on the real
  target branch when there's a merge race between sibling branches — worth verifying real ancestry
  directly when something "already merged" keeps behaving as if it weren't.
- **Where I'm weak:** the integration-branch/default-branch mismatch was identified again this week as
  the root cause of Monday's cleanup, but the actual fix (changing the repository's default branch or
  the auto-close target) still hasn't been proposed — it keeps getting absorbed as periodic manual
  cleanup instead of solved once.
- **Next-week focus:** propose and land a fix for the integration-branch/default-branch mismatch to
  stop the recurring manual issue-closing; close out the two calendar-feature issues still open at
  week's end; follow up on the invoice-download bug documented this week (no fix yet).
